# 앞으로 성장할 연구 주제를 찾아주는 에이전트

2026 NAIS AI 해커톤 본선 · 팀 AI Strategy · 트랙 ① 연구 기획·탐색

## 한 줄

연구 주제를 넣으면, 그 주제를 판단할 근거를 한 장으로 돌려준다.
논문 수보다 먼저 바뀌는 신호를 찾고, 그 신호가 과거에 얼마나 맞았는지를 같이 보여준다.

## 풀려는 문제

연구 주제를 고를 때 쓰는 방법은 대부분 사람 손과 시간으로 한다.

- 논문·특허 기록은 일이 벌어진 뒤에 나온다.
- 동향조사는 한 번에 몇 주가 걸린다.
- 전문가에게 묻는 조사는 몇 년에 한 번이다.

그래서 세부 주제마다 자주 확인하기 어렵다.

## 에이전트가 하는 일

| # | 일 | 내용 |
|---|---|---|
| 1 | 읽는다 | 논문 기록에서 건수가 아니라 내용이 바뀌는 것을 본다 |
| 2 | 대조한다 | 논문의 흐름을 산업의 사건과 같은 시간축에 놓는다 |
| 3 | 찾는다 | 그 주제를 실제로 발표한 기관과 사람을 찾는다 |
| 4 | 검증한다 | 같은 방법을 과거 시점에 돌려 실제로 맞았는지 확인한다 |

판정은 연구자가 한다. 이 도구는 정식 조사를 대신하지 않는다.

## 데이터

- 사전에 보유한 데이터는 없다. 수집·구조화·분석 전 과정을 본선 기간에 이 저장소의 코드로 수행한다.
- 출처: [OpenAlex](https://openalex.org) 공개 API (CC0)
- 수집한 원본과 수집 시각은 `data/`에 남긴다.

본선 중 계속 갱신한다. 체크된 것만 구현된 것이다.

- [x] 수집: OpenAlex에서 ECTC 2018~2026 발표 3,420편 (`src/collect.py`)
- [x] 읽는다: 주제별 연도 추이와 내용 신호 (`src/analyze.py`)
- [x] 대조한다: 산업 사건을 같은 시간축에 표시 — 사건 목록은 사람이 적는다 (`data/events.json`)
- [x] 찾는다: 주제별 기관 · 저자
- [x] 검증한다: 기준 연도 2021 · 2022 · 2023으로 돌아가 신호가 맞았는지 센다
- [x] 화면: 주제 입력 → 근거 한 장, 기준 연도 뒤를 가렸다가 여는 기능 (`web/index.html`)
- [x] LLM 에이전트: 한글 질문 → 스스로 도구를 골라 부름 → 근거 도구가 달린 문장 작성 (`src/agent.py`)

- [x] 다른 분야 신호: 사람이 적은 연결 가설에 따라 다른 분야 논문 수를 같은 화면에 표시 — 검증 전 (`src/upstream.py`, `data/links.json`)
- [x] 다른 분야 1개에 같은 방법 적용: 태양광 학회 PVSC (`python src/collect.py pvsc && python src/analyze.py pvsc`)
- [x] 기관 · 저자의 연도별 발표 흐름, 연구 공백 지도(문제 × 방법, LLM 분류 · 코드 집계), BibTeX 내려받기

## 지금까지 나온 결과 (2026-09-30 수집분)

모은 기록: 패키징 학회 다섯 곳(ECTC · EPTC · ICEPT · ESTC · ITherm) 10,829편 + 태양광 학회(PVSC) 5,170편.

**지표 하나(내용)만 쓸 때** — 제목에서 양산 문제 낱말의 비중이 10%p 넘게 오른 활발한 주제가 3년 뒤 1.5배 이상 커졌나. 일반 낱말은 LLM으로 걸러냈다.

| 돌아간 시점 | ECTC: 고른 주제 → 커진 것 | ECTC: 고르지 않은 주제 → 커진 것 |
|---|---|---|
| 2021 | 7개 중 0개 | 50개 중 2개 |
| 2022 | 9개 중 0개 | 57개 중 5개 |
| 2023 | 15개 중 4개 (27%) | 69개 중 9개 (13%) |

세 번 중 한 번만 나았다. 태양광에서는 세 시점 모두 통하지 않았다 (6개 중 0 · 10개 중 1 · 13개 중 1).

**지표 네 가지를 겹칠 때** (`python src/combo.py ectc pkg`) — 내용 · 사람(새 기관이 70% 이상) · 흐름(비중이 1.2배 이상) · 전파(발표하는 학회 수가 늘어남). 지표 정의는 결과를 보기 전에 정했다.

| 켜진 지표 수 | ECTC (세 시점 합 207개) | 패키징 다섯 곳 (506개) |
|---|---|---|
| 0개 | 56개 중 4개 (7%) | 114개 중 6개 (5%) |
| 1개 | 74개 중 6개 (8%) | 180개 중 10개 (6%) |
| 2개 | 48개 중 5개 (10%) | 116개 중 12개 (10%) |
| 3개 | 25개 중 4개 (16%) | 87개 중 11개 (13%) |
| 4개 | 4개 중 1개 | 9개 중 0개 |

두 개 이상 겹친 주제는 세 시점 모두에서 0~1개인 주제보다 더 자주 커졌다. 그래도 커진 것은 열에 한둘이다. 맞히는 도구가 아니다.

**정정과 추가 확인** (`python src/research.py`, 9/30 밤)

- 위 표의 "패키징 다섯 곳"에는 ECTC가 들어 있다. ECTC를 뺀 네 학회만으로 같은 계산을 하면 차이가 없었다: 두 개 이상 145개 중 13개(9%) 대 미만 211개 중 18개(9%).
- 대신 **ECTC에서 잰 지표**는 다른 네 학회에서의 3년 뒤 성장과 맞았다: ECTC에서 지표가 두 개 이상 겹친 주제 77개 중 19개(25%)가 네 학회에서 커졌고, 미만은 130개 중 12개(9%)였다. 시점별로 2021년 15% 대 3%, 2022년 15% 대 13%, 2023년 40% 대 9%. ECTC에서 먼저 커진 주제는 20개 중 9개가 네 학회에서도 커졌다(안 커진 주제는 187개 중 22개). 앞서가는 학회에서 재야 한다는 뜻으로 읽힌다. 다만 이 확인은 위 결과를 본 뒤에 생각한 것이다.
- **지표를 여섯 개 더 넣어 봤다**: 기업 · 국가 · 가속 · 협업 · 분산 · 분화. ECTC에서 골라 보니 기업 · 가속 · 협업이 좋아 보였고, 일곱 개를 겹치면 ECTC에서는 네 개 이상 37개 중 10개(27%) 대 170개 중 10개(6%)였다. 그러나 ECTC를 뺀 네 학회에서는 64개 중 6개(9%) 대 292개 중 25개(9%)로 **재현되지 않았다.** 그래서 화면의 지표는 네 개 그대로 둔다. 국가 · 분화는 두 기록 모두에서 반대 방향이었다.
- 인용 수는 지표로 쓰지 않았다. 공개 기록의 인용 수는 오늘까지 쌓인 값이라 과거 검증에 넣으면 미래를 미리 보는 셈이 된다.

## 시연 순서 (5분 발표 중 약 90초)

1. 첫 화면: 입력창 아래 "지금 되는 범위와 한계"를 먼저 보여준다.
2. "지금 뜨는 주제 찾아줘" → 에이전트가 후보 찾기를 고른다. 후보 카드의 "겹친 지표"를 본다.
3. 후보 하나(유리 코어)를 눌러 근거 한 장: 흐름, 산업 사건(출처 링크), 기관, 에이전트의 설명.
4. "이 방법, 과거에 맞았나?" → 2023년으로 돌아가 가린 것을 연다. 맞은 것과 틀린 것이 카드마다 나온다.
5. 탭: 관계(학회 — 기관 — 저자 — 세부 주제), 전파, 공백 지도, 기획서 초안을 짧게.
